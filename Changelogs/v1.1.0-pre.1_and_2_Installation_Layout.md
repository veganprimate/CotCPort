## ARCHIVE: Layout of the archives (`v1.1.0-pre.1` and `v1.1.0-pre.2`)

* `CotCPort_Base-[version].7z` contains the base mod files which **must** be installed. The DLL mods **depend on each other**.
* `CotCPort_Extras-[version].7z` is a **loose collection** of DLL and pak mods. **None** of them are **necessary**, and they **do not depend on each other**.

The internal layout of the archives mirrors the layout of `OCTOPATH TRAVELER 0/Octopath_Traveler0/` to make installation as easy as **extracting** the archives **into the game's folder**. 

Installation may require you to **replace** a number of DLLs under `Binaries/Win64/`, please also ensure `CotCPort_notex_p.pak` from v1.0.0 of the CotCPort is **removed** from `Content/Paks/` before starting the game as `CotCPort_DataBase_p.pak` is supposed replace it but due to differing filenames, won't do that on its own.
Otherwise, please see [Installation](https://github.com/veganprimate/CotCPort#installation) .

### Explanation of the different files and mods
#### Root-level DLLs under `Binaries/Win64/`
##### `OT0KingshipLoader.dll` and `dwmapi.dll`
These are related to **initializing** the DLL mods. A proxy `dwmapi.dll` is placed beside the game executable so Windows loads it first through the **normal DLL search order**. That proxy is not the real Windows DWM library; it is a small bootstrap shim. It loads/forwards to the real system `dwmapi.dll`, then boots `OT0KingshipLoader.dll` when the game starts.

`OT0KingshipLoader.dll` is the actual mod loader. It initializes the runtime API inside the live OT0 process, discovers mod DLLs under `Binaries/Win64/KingshipMods/`, and accepts either flat DLLs like `KingshipMods/[Mod Name].dll` or folder-style mods like `KingshipMods/[Mod Name]/main.dll`.

For each loaded mod, the loader creates/provides a shared `ModContext`. That context is the **bridge** between the **mod DLL** and the **running game process**: it exposes the game module image, runtime paths, logging, versioned RVA/native-function resolution, memory patch helpers, hook installation helpers, event/lifecycle helpers, and other API services.
Individual mods such as `CotCPort_Ailments.dll` then use that context to install hooks into native OT0 functions, call recovered game functions, patch memory, or run mod logic safely inside the game process.

A more detailed explanation with follow with the release of v1.1.0 and the publishing of the mod source, likely in the coming few days.

##### The MinGW DLLs `libgcc_s_seh-1.dll`, `libstdc++-6.dll`, `libwinpthread-1.dll`
These are **unmodified** **official** MinGW DLLs for the mod loader and DLL mods but not included with OT0 by default.
**Only `libwinpthread-1.dll` is explicitly imported** by the other DLLs and **necessary** because the Windows cross-build (I don't run Windows) used an `x86_64-w64-mingw32` toolchain with the POSIX threading model.

The MinGW GCC runtime support DLL `libstdc++-6.dll` and MinGW/libstdc++ C++ standard library runtime `libstdc++-6.dll` are included for compatibility's sake but **likely not strictly needed**; I can run the game fine without them but **include them if uncertain**.

#### Under `Binaries/Win64/KingshipMods/`
This is the mod folder for the mod loader, configuration files for every C++ mod can be found under `Binaries/Win64/KingshipConfig/`. I made sure to make every mod **highly configurable**.
Mod-generated (crash) dumps are stored at `Binaries/Win64/KingshipDumps/`, and `Binaries/Win64/KingshipLogs/` stores logs for the individual C++ mods.

For this prerelease, the mods are configured to **log more than usual**, if this is causing performance issues on your end, you can disable this in the mods' configs.

##### `CotCPort_Ailments.dll`
The biggest of the C++ mods in terms of content, it rigorously provides the **runtime backing** needed for **CotC's ailments / status effects**, in the future, this will include OT1/OT2 status effects like _Petrification_ and custom ailments such as Zelig's _Solistian Spirit_ as well.

Almost all status effects depend on native game logic in OT0 and CotC, very little beyond visual presentation is specified in DB assets such as `SkillAilmentType`, even `SkillAilmentType.m_Label` is effectively ignored at runtime in favor of the IDs (`SkillAilmentType.m_id`), which appear to correspond to the internal enum `ESKILL_AILMENT_TYPE`. 
As such, extensive runtime backing was needed, the mod currently covers the following status effects / provides the following `SkillAilmentType` rows with extra runtime backing:
1. **Stat/status/calc bridges for CotC-imported (de-)buffs**
 - ordinary **stat up/down**
 - **status-limit** rows
 - **damage-rate** up/down, including special buffs such as Multi-Hit Damage Reduction
 - **critical-damage** rate rows
 - **race** slayer / **race** reduction
 - **max HP debuff** handling
 - **SP cost** increase/reduction/no-cost style rows
 - **BP recovery** / **BP repair** modifiers
2. **BP / boost / resource behavior**
 - Starseer Mydia's **BP Stock**
 - **BP recovery block** / `INVALID_RECOVER_BP`
 - **BP repair** up / **skip**
 - **Boost Lv Change** payment logic and **BP UI adjustment** (e.g. the Final Emperor's `Boost Lv Change (2/4/6)` which has him consume BP in levels 1→3→5)
 - (WIP) Fighting Spirit / `FIGHTING_SPIRIT`, `FIGHTING_SPIRIT_2`: BP is still required for boost selection, but BP/stock consumption is restored after boost/cost paths in the completed patch. The patch explicitly extends the `StaticConsumeCost` hook installation for Fighting Spirit and adds BP snapshot/restore logic.
3. **Weakness / resistance / shield behavior**
 - CotC added-weakness and bind-weak rows (**weakness infliction**, still buggy UI-wise, in particular, OT0 cannot display more than 8 weaknesses at a time)
 - weak-lock / robust bind-weak behavior
 - force-weak / ailmented-skill weakness behavior
 - weak-damage-rate modifiers
 - shield slip / shield damage rows (Shock, Frostbite, Dizziness, Corrosion, etc.)
 - Stile Marino / `CONVICTION_2`
 - Evil Eye / `AWAKEN_EYES`
 - Mana Leak / `LEAKAGE`, via a `GetSkillAttribute` bridge that can add a magic lane to physical/weapon actions
4. **Avoidance, nullification, crit, and hit-resolution behavior**
 - **`DIZZINESS` miss behavior**
 - **ignore evasion** / `DISABLE_DODGE`
 - **ignore damage nullification** / `DISABLE_ZERO_DAMAGE`
 - **target-type-specific dodges**, such as Kagemune's random-target dodges
 - **damage-limit** increase/decrease/ignore
 - **magic/elemental crit** enable via `IsMagicCriticalEnabled`
 - **attacker-side force critical** via `IsForceCritical`
 - **defender-side "receive critical damage"** / `DEBUFF_CRITICAL_DAMAGE` via `AQPBattleManager::CriticalCheck`
6. **Action/target rewrite behavior**
 - **cover / intercept** target redirection to OT0-native functionality
 - **Confuse / Marionette action override**: random same-side basic attack, with default fallback rates of 50% for Confuse and 100% for Marionette
7. **Death / revive / survival behavior**
 - **reraise classifier** rows
 - **invalidate revive** rows
 - 1-HP survival / **Unsinkable**-style rows
 - **necromancy/death-puppet** revive **side effects**
 - some death-mode/resource-related marker behavior

**Not yet implemented in `CotCPort_Ailments` are**:
 - `688 PLAY_SKILL_RANDOM`
 - `938 MAGIC_ATTACK_AND_SKILL`
 - `1019+ ACTION_AND_SKILL`
 - `1491 JUMP_ATTACK` / **Dragoon Jump**
 - **Damage-Reduction bypasses** seen in e.g. the Final Empress's and Auron's skills 
 - **repeat-action** rows like `449 SSHIFT_03_REPEAT_SKILL`, `542 SSHIFT_REPEAT_SKILL_JN`, `784 ALWAYS_SUCCESS_REPEATSKILL`; this also includes **pursuits**
 - **Divine Beast** repeat families (primarily because the logic around Divine Beasts has to first be implemented)
 -  **Style Shifts/Latent Powers**, the related ailments are mostly DB-backed and thus no big problem of their own, what is finnicky is adding a new element to the Battle UI to trigger the shift and have this not consume an action
 - **asset-backed visuals** like CotC's white boost aura at Boost Lv 6
 - **per-avail/skill payload damage limit increases** have not yet been added. Only status effect-based damage limit increases work right now, not ones innate to skills from CotC 
 - probably dozens more I am forgetting right now; what has been added has also **not been extensively tested** yet
 
##### `CotCPort_Conditions.dll`
CotC has many **battle condition IDs** and **branch conditions** that OT0 does not know, and at other times, OT0 uses the same ID for a different purpose (Example: `10803`, in OT0, it's `previous SP use >= Param`, whereas in CotC, it appears to be related to action-order). These are crucial for properly implementing Enemy AI, skill invoke conditions, and more.

This mod provides the missing runtime-backing for those, it is not as complete as `CotCPort_Ailments.dll` however, partially because the meaning has to be manually recovered from CotC first.

##### `CotCPort_Stats.dll`
As the name implies, this mod is supposed to provide OT0 with **missing runtime backing** w.r.t. **character/enemy/accessory/item stats**, in the future this will likely include pet stats, CotC-unique enemy stats such as `m_EquipAtk`/Grade, and more.
Right now, it is limited to **allowing accessories and equipment to bypass the stat limits**. This is meant to **replicate CotC's** behavior of **no effective stat limit** all while **preventing infinitely high stats via nut abuse** as only accessories and equipment are able to bypass the stat limit.

##### `CotCPort_Menus.dll`
This mod provides the **missing runtime backing** for **edited menus** and (in the future) **entirely new** ones. It depends on `CotCPort_BluePrints_p.pak`, which contains edited BP assets and soon will contain entirely custom ones.

Right now, this mod does 3 rather elementary things:
 - Adds **Solistia** and **Dreadborn Orsterra** to the **world switcher**
 - **Fixes a bug** where the display showing which units have the selected learned (support) skill equipped causes the game to crash once more than ~60 characters have the same one equipped
 - **Extends** the **support skill tab** in the Learn Skills and Equip Skills menus **beyond 4**. This is has been added because even after collapsing identical skills in the respective characters' skill boards to one, I was ultimately left with more than 4 support skills per characters at average, and many special features depend on those; without this mod, you cannot enable support skills beyond the 4th slot. I will likely return to 4 slots in the future once I have made a decision on which support skills to keep and/or merge.

##### `CotCPort_BattleUI.dll`
**Similar to `CotCPort_Menus.dll`** but spezialized in **Battle UI**, also dependent on `CotCPort_BluePrints_p.pak`.

Right now, this mod provides the game with the necessary code for displaying damage values beyond 5 digits.
**WARNING: Without this mod, `CotCPort_BluePrints_p.pak` will just append 9s to every damage value !!!**

 - The **crash** which occurs when **scrolling down too far** in the menu (when the list has more than 24 entries/becomes scrollable) has been **fixed**. For this, I will just quote my Discord post:
My goal with it this mod to create something to help with **debugging custom maps**/**edited maps**, largely because:
 - the **presentation** of custom-made maps can be **unpredictable in-game**
 - **FModel's map viewer** tends to display textures **wrong** and has **extremely basic shading**, making it an **unreliable visual authority** for map creation/editing
 - you generally are **not able to use Unreal Editor's graphical editor** without a lot of effort to resolve the `/Script/*.*` dependencies.
It will go hand-in-hand with the **map editor fork** for **FModel** I am developing and may supersede it depending on how difficult it will be to transform the running game into a proper map editor.

Right now, it has two major features:
 - a **visual map picker** that allows you to **teleport to any map** listed under `MapListTable`
 - a **mode** that allows your character to **walk on any Unreal mesh** that has **innate collision data** (toggled by pressing F4 / RB)

This will allow you to walk around reconstructed CotC maps which currently lack floor collision carriers and also reach the entrances to newly added locations where the OT0 map currently does not allow you to walk (e.g.: the Abandoned Mines, the bridge to I'Cirlo Pass, Cave of Laments, etc.).

As manually creating floor collision meshes for hundreds of new maps will still take a long time, this will **remain the primary way of walking around the CotC-exclusive maps for a while**. 

##### (Optional) `RemoveMCPartyLockMod.dll`
The name says everything, this mod **removes the lock** from the **main character** in the Formation Menu, allowing you to freely build your party.

It is **untested** how not having the Ringbearer in the party will **affect OT0's main quest**.
Pivotal moments in the main story, such as the **mirror battle** against the **MC's shadow**, or **illumination events** like in the **Wishvale Utopia** event or **snow world** sequence **prior to fighting the final boss** may not work without the MC in the party.
There are also passages where everyone besides the MC is **temporarily removed/unrecruited** from the party. It is **untested** how the game would react to the MC being unrecruited.
Lastly, **special skills** the Ringbearer gains as he progresses through the Mast**er and Bestower questlines** may be assigned to the party leader if the MC is not in the party.

##### (Optional but **highly recommended**) `CorruptDataProbeMod.dll`
This mod **produces detailed crash dumps and crash logs** under `KingshipDumps/`.

Beta-testers have noted that the large dump creation can cause the game to become **significantly laggier** and the mod is therefore optional by default.
However, given that this is a pre-release version and many bugs have not yet been ironed out, I would greatly appreciate it if you could help expedite my bug-fixing process, even if it means lower framerates.

The `Z` in the filename ensures this pak is loaded last and therefore is not overrided by anything else (though given that `D` precedes `N` in the alphabet, `CotCPort_normal_difficulty_p.pak` would still override `CotCPort_DataBase_p.pak`'s assets). 

Future versions of the mod / v1.1.0 will probably have this pak and `DataBase` switch roles: `CotCPort_DataBase_p.pak` will by default be of normal difficulty and the hard mode will be an optional pak to add on top of the base paks.
In any case, out of respect for your hard drive space and to make switching between the two versions easier, I will no longer be uploading two huge versions of the same DataBase pak when I ultimately only modify a small number of assets; even if that may change in the future, it is unlikely to justify an entirely seperate DataBase pak.
