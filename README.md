A mod for **OCTOPATH TRAVELER 0** that aims to integrate as much content as possible from **OCTOPATH TRAVELER: Champions of the Continent** (Global, Japanese, and Chinese versions) and the **other Octopath games too** into OCTOPATH TRAVELER 0.
- Play all **280+ characters** from CotC complete with skill boards, voicelines, character art, and custom Wishvale integration, including **20+ fully custom playable characters**

[All the different playable characters in `v1.1.0-pre.3-hotfix2`](https://github.com/user-attachments/assets/88e7a927-889b-43bd-9be6-5b92d16d8223)

## Installation
Head to [Releases](https://github.com/veganprimate/CotCPort/releases) and download the archives `CotCPort_Base.7z` and `CotCPort_Extras.7z` of the latest (pre-)release. 

 - `CotCPort_Base.7z` contains the **base mod files** which **must be installed**. The DLL mods depend on each other.
 - `CotCPort_Extras.7z` is a loose collection of DLL and pak mods. **None of them are necessary**, and they **do not depend on each other**.

The archives are arranged to mirror the internal game folder:
```
OCTOPATH TRAVELER 0/
└── Octopath_Traveler0/
    ├── Binaries/
    │   └── Win64/
    └── Content/
        └── Paks/
```        
The files from the archive readily **merge into** the existing `Octopath_Traveler0` folder. Extract them into `OCTOPATH TRAVELER 0/`, see the sections **below** for details on where to find this folder depending on your platform and what to look out for.

>[!IMPORTANT]
> Do **not** accidentally create an **extra nested folder** such as:
> ```
> Octopath_Traveler0/Octopath_Traveler0/...
> ```
> or
> ```
> Octopath_Traveler0/CotCPort_Base/Octopath_Traveler0/...
> ```
> The **final** game folder layout should be **roughly** like this:
> ```
> Octopath_Traveler0/
> ├── Binaries/
> │   └── Win64/
> │       ├── Octopath_Traveler0-Win64-Shipping.exe
> │       ├── (+other non-mod files)
> │       ├── dwmapi.dll
> │       ├── OT0KingshipLoader.dll
> │       ├── libwinpthread-1.dll
> │       ├── (+extra MinGW DLLs if needed)
> │       ├── KingshipConfig/
> │       │   └── (DLL mod .ini config files)
> │       └── KingshipMods/
> │           └── (DLL mods)
> └── Content/
>     └── Paks/
>         ├── pakchunk0-[your platform].pak
>         └── (pak mods)
> ```

>[!NOTE]
> _For more details on the files within both archives, see the section **Layout of the archives** in the release notes for [v1.1.0-pre](https://github.com/veganprimate/CotCPort/releases/tag/v1.1.0-pre)._

>[!NOTE]
> Installation may require you to **replace** a number of DLLs under `Binaries/Win64/`, please also ensure `CotCPort_notex_p.pak` from v1.0.0 of the CotCPort is **removed** from `Content/Paks/` before starting the game as `CotCPort_DataBase_p.pak` is supposed replace it but due to differing filenames, won't do that on its own.

> [!WARNING]
>  As of now, there are **no Switch-compatible versions** of the **DLL mods** developed for the CotCPort nor an equivalent **native runtime layer** for installing hooks/detours/etc. The Switch version is also based on v1.0.4.0 of OCTOPATH TRAVELER 0, not v1.0.8.0 which the mods were based on.
>
> It is **untested** whether the DLL mod loader is **compatible** with the **Microsoft Store** version of OT0 v1.0.8.0. The MS Store Win64 Shipping executable **may be different** to the Steam version's, thus displacing RVAs.
>
> Nintendo Switch and MS Store players will possibly have to **constrain** themselves **to only using the paks** from the prerelease, more info below.
 
### Steam
Extract the archive(s) under `steamapps\common\OCTOPATH TRAVELER 0\`.

To find the folder of your OCTOPATH TRAVELER 0 installtaion

1. Open **Steam**.
2. Go to your **Library**.
3. Right-click **OCTOPATH TRAVELER 0**.
4. Select **Manage** → **Browse local files**.
5. Steam will open the **game's installation folder**.

a typical **Windows** path may be
```bash
C:\Program Files (x86)\Steam\steamapps\common\OCTOPATH TRAVELER 0\
```

a common **Linux** path is:

```bash
~/.local/share/Steam/steamapps/common/OCTOPATH TRAVELER 0/
```

or

```bash
~/.steam/steam/steamapps/common/OCTOPATH TRAVELER 0/
```

or for **Steam Deck** users who have installed OCTOPATH TRAVELER 0 on a **microSD card**

```bash
/run/media/deck/<SD-card-name>/steamapps/common/OCTOPATH TRAVELER 0/
```
>[!NOTE]
> #### Note for Linux users
> If the DLL++ mod loader is **not initializing** on your end despite having followed the installation instructions for `Binaries/Win64/`, you can try the following launch options:
> ```bash
> WINEDLLOVERRIDES="dwmapi=n,b" %command%
> ```
> Wine interprets `n,b` as native first, then builtin. Without this override, Proton _may_ select its builtin `dwmapi.dll` instead of my proxy beside the executable. That means the game launches normally, but my `dwmapi.dll` never executes and `OT0KingshipLoader.dll` is never loaded.
>
> You can also set this override in the** Wine prefix** you are using directly:
> ```bash
> PREFIX="/path/to/your/wine-prefix"
> 
> WINEPREFIX="$PREFIX" wine reg add \
>  'HKCU\Software\Wine\DllOverrides' \
>  /v dwmapi \
>  /t REG_SZ \
>  /d native,builtin \
>  /f
> ```
> you can remove it by running
> ```bash
> WINEPREFIX="/path/to/your/wine-prefix" wine reg delete \
>  'HKCU\Software\Wine\DllOverrides' \
>  /v dwmapi \
>  /f
> ```

### Microsoft Store
1. Rename the pak suffix from lowercase `_p` to uppercase `_P` for all of the paks
2. Open the **Xbox App** on your PC, right-click **OCTOPATH TRAVELER 0** in your installed games list on the left sidebar, and select **Manage**
3. Click on the **Files** tab
4. Click **Browse**
5. Extract the archive(s) under `<game install folder>\Octopath_Traveler0\`

>[!WARNING]
> As compatibility of the DLL mod loader with the MS Store version of OT0 is still **unproven**, and if it turns out to be **negative** on your system (check if logs have been generated under `Binaries/Win64/KingshipLogs/`), please **remove `CotCPort_BluePrints_P.pak`** from your `Content/Paks/` folder as this pak is dependent on the DLL mods `CotCPort_Menus` and `CotCPort_BattleUI`. 

### Switch (real hardware/Atmosphère)
The Switch version should be treated as **pak-only**. **The Windows DLL mods do not work on Switch** and **no replacement has been made yet**.

The Switch installation uses **Atmosphère LayeredFS**. You are not replacing files inside the game install directly. Instead, you place the modded RomFS-style files on the SD card, and Atmosphère overlays them when the game starts.
The OT0 title ID is `01005270232F2000`, create this folder on the SD card:
```
sdmc:/atmosphere/contents/01005270232F2000/romfs/Octopath_Traveler0/Content/Paks/
```
place every pak **besides `CotCPort_BluePrints_p.pak`** inside:
```
sdmc:/atmosphere/contents/01005270232F2000/romfs/Octopath_Traveler0/Content/Paks/CotCPort_DataBase_p.pak
sdmc:/atmosphere/contents/01005270232F2000/romfs/Octopath_Traveler0/Content/Paks/CotCPort_Maps_p.pak
sdmc:/atmosphere/contents/01005270232F2000/romfs/Octopath_Traveler0/Content/Paks/CotCPort_Sounds_p.pak
sdmc:/atmosphere/contents/01005270232F2000/romfs/Octopath_Traveler0/Content/Paks/CotCPort_Textures_p.pak
```
All the paks in `CotCPort_Extras.7z` are compatible as well.

>[!CAUTION]
> Being pak-only, you will only be able to experience **a small fraction** of the **modpack's features**. The new tables in the DataBase pak under `/Game/Local/DataBase/CotCPort/` naturally will not work either. 
> The Switch version also currently is based on** OCTOPATH TRAVELER 0 v1.0.4.0**, not **v1.0.8.0** as the PC version. As such, it cannot be guaranteed the mod's assets do not make references to other assets or rows in the DB that do not exist in the Switch version.
> On July 13th, Team Asano announced a [free content update coming to Octopath Traveler 0](https://www.youtube.com/watch?v=NgaqSDoJTWg), given that this is a content update, it is likely to release on the Switch as well, after which the Switch and PC versions may be back to being on the same version.

### Switch (Emulator)
Analogous to the real hardware, this platform should also be treated as **pak-only** for the same reason.
Create a mod with the following **internal** layout: 
```
romfs/
└── Octopath_Traveler0/
    └── Content/
        └── Paks/
             ├── CotCPort_DataBase_p.pak
             ├── CotCPort_Maps_p.pak
             ├── CotCPort_Sounds_p.pak
             ├── CotCPort_Textures_p.pak
             └── (+ any of the pak mods in CotCPort_Extras.7z)
```

### Other platforms

## How to recruit the new travelers
Characters' **traveler stories** currently serve as their recruitment events, however, that only covers 140 out of the 280+ newly added characters. I am planning on adding **unique recruitment events** for each and every new playable character in this mod but that will still take some time.

For now, you can use the **optional** pak mod `RecruitEvent_p.pak` in the `CotCPort_Extras.7z` archive to recruit all character this mod provides at once. 
For that, please head to **Wishvale Trail** and speak with the **Forgetful Squirrel**, pictured below:

<img width="1239" height="541" alt="image" src="https://github.com/user-attachments/assets/a39b0888-f820-462b-81c0-1a747ab59528" />

A prompt with **four options** will pop up:
 1. Recruit all mod characters + Add them to Wishvale
 2. Recruit all mod characters
 3. Unrecruit all mod characters
 4. Remove all mod characters from Wishvale

<img width="1920" height="1080" alt="image" src="https://github.com/user-attachments/assets/26b2bbef-698c-4d4a-95f6-1b14b5391ec4" />


When an update to the mod introduces new playable characters, you can recruit them by **talking to the same NPC again** provided `RecruitEvent_p.pak` is in your paks folder.

>[!NOTE]
> **Why re-recruiting is safe**: The visible add-member effect is **suppressed** for already recruited characters because `EntryPlayerCharacter` returns `false` for those, and opcode `10029  EvCmAddPartyMember` does not force the dialog, but that does not mean `10029` is skipped for already recruited characters. It is just that what it does is neglegible: an already recruited player may still be processed, have their HP/SP healed, position them in the party, refresh active party cue sheet, etc. They will **not** lose their equipment or equipped skills, have their stats reset, or be recruited twice.

> [!WARNING]
> Be careful about recruiting characters too early now that the recruit event is at **Wishvale Trail**. During the prologue, all of your party members have their **equipment slots locked**. Any character that is recruited during this quest-state also has their equipment slots locked. This effect is **not undone** by completing the prologue, you will have to **re-recruit** all the affected characters


> [!WARNING]
> The stats of the recruited characters are scaled according to **whoever interacts with the squirrel**, i.e. depending on who the party leader is (i.e. in the upper left corner in the formation menu)
